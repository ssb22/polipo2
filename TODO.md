* [External redirector inconsistencies with Squid](https://github.com/jech/polipo/issues/15) `MEDIUM-HIGH, owner decision. The issue body is only a link to Debian bug 678470 (closed in 2019 only because the Debian package was removed, never fixed), so the substance is there. Squid's url_rewrite_program sends each request as one line: URL, client_ip/fqdn, user, method, then optional key=value pairs. Polipo sends only the URL, so the three mandatory fields are missing. The report is about the request side only. The fix is small and testable with a helper script that logs the lines it receives, using "-" where a field is unknown. Decision needed: existing Polipo-specific redirectors that treat the whole line as the URL would break if extra fields appear, so choose between a config option (off by default) and a compatibility break. I believe newer Squid versions have extended this format since 2012 (I have not checked), so an agent should confirm which Squid version's format to target.`

* [Add config setting which preserves host header](https://github.com/jech/polipo/pull/30) `MEDIUM, owner decision. The PR is a naive option (useClientHostHeader) that the maintainer rejected: objects cached under the old setting would not obey the new one. His suggested design: add a host field to struct object, store an x-polipo-original-host header in the on-disk cache, and generate the Host header in httpWriteObjectHeaders (carefully, since that function serves both network output and disk-cache formatting). Reading the diff, it also seems to send no Host header at all if the client sent none (an HTTP/1.0 client), so do not just resubmit it. Owner decision: accept the simple option documented as for cacheless use, or do the object-level design.`

* [Crash when browsing this url](https://github.com/jech/polipo/issues/68) `MEDIUM, and the best lead for the crash family (22, 23, 46, 68, 74). Valgrind trace, reproduced on x86-64: a 120-byte connection struct is freed in httpServerFinish (server.c:1315), called from httpServerRestart, then a scheduled stream event runs httpServerDirectHandlerCommon on it (server.c:2597). gdb shows the stale struct with fd=-1 and request=NULL. Suggested approach: build with AddressSanitizer, use a mock origin that closes or restarts server connections mid-response to trigger httpServerRestart, and see whether ASan reports the same stack. * [Support usernames and passwords in URLs](https://github.com/jech/polipo/issues/75) `MEDIUM-HIGH, depends on the owner decision in 76. * [adding support for ignoring credentials in URL](https://github.com/jech/polipo/pull/76) `MEDIUM-HIGH, owner decision. The PR just skips the credentials. The maintainer asked whether the userinfo should be sent to the server and why a proxy should care; the author pointed at RFC 3986 and wants passthrough. Reading the diff: the scanning loop looks for '/' without checking the URL length, so it could read past the end of a URL with no slash. Do not reuse it as is. Options: (a) parse past the userinfo and ignore it, (b) turn it into an Authorization: Basic header as curl does, (c) pass the URL through unchanged. Do 75 and 76 as one task.`
